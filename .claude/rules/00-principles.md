# 00 基础原则（始终生效）

> 适用：所有会话、所有代码。违反本文件即拒绝继续。
> 编号体系：00 基础 → 01 技术栈 → 02 目录/命名 → 03 UI → 04 后端 → 05 前端 → 06 API → 07 文档 → 08 流程 → 09 测试 → 10 安全 → 11 ADR → 12 协作 → 13 i18n → 14 时区。

## P1 权威来源

- `docs/架构设计方案.md` 是唯一设计权威。代码与设计冲突时，先改方案（走 ADR，见 11），再改代码。
- `CLAUDE.md` 是 AI 入口索引；详细规则在 `.claude/rules/`。

## P2 铁律三条（本项目硬约束，任何人任何场景不可违背）

1. **禁 HDFS DataNode RPC 直连**：平台到集群一律走"单端口、无回调"协议（REST / JDBC / Thrift），集群地址存 IP，不依赖 hostname 解析。
2. **平台不做计算**：所有 SQL 与作业下发集群（Hive/Spark/DS）执行，本地只"管、写、调、问"。
3. **不改动集群**：不修改 VM 任何组件配置、不删除/覆盖集群已有数据。新增集群侧组件必须标注"可选增强"并说明理由。

## P3 资源红线

- 平台常驻内存 ≤ 2GB（不含 Ollama）。禁选重型元数据栈（DataHub/OpenMetadata/Atlas/Linkis+DSS）。
- 禁 Docker / Docker Compose / K8s：一切以原生进程 + `scripts/start.ps1` 启动。

## P4 简单性

- KISS / DRY / YAGNI。不为假设的未来需求加抽象；三行相似代码好过一个过早封装。
- 不做云平台级设计：单机自用、单用户低并发，方案必须务实可落地。

## P5 最小修改

- 只改任务相关的代码；不顺手重构、不加无关注释/类型标注。新增文件仅当确实必要。

## P6 版本以实测为准

- 不假设集群 Hadoop/Hive/Spark 版本。对接方式以 `docs/环境探测结果.md` 实测为准；不确定处标注"待环境探测确认"，禁止编造。

## P7 待探测即标注

- 任何依赖探测结果的细节（端口、账号、版本、协议）必须显式标注"待环境探测确认"，不得写死。

## P8 决策落盘

- 所有影响代码的决策必须写成文件进仓库。脑子里想到但没写下来的约定，对 AI 而言不存在。

## P9 安全默认

- 涉及集群连接串、密码、token 的代码一律走环境变量 + AES 加密字段，禁明文入库/入日志。
