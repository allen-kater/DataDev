# 07 文档管理（始终生效）

> 目标：影响代码的决策都写成文件进仓库；文档是给"人 + AI"读的，不是装饰。

## 文档层级

| 文档 | 位置 | 职责 | 变更时机 |
|---|---|---|---|
| 架构设计方案 | `docs/架构设计方案.md` | **唯一权威**：架构/选型/端口/数据模型/分阶段计划 | 走 ADR（见 11） |
| 环境探测结果 | `docs/环境探测结果.md` | Phase 0 实测：版本/端口/IP/账号/网络模式 | 每次探测后更新，方案中的"待探测"据此填实 |
| AI 入口 | `CLAUDE.md` | 技术栈/结构/API 索引/流程红线 | 技术栈、端点、阶段变化时同步 |
| 规则 | `.claude/rules/00~14.md` | 可执行约束 | 规则新增/修改走 ADR |
| 决策记录 | `docs/ADR/`（ADR-001.md 递增） | 技术决策上下文 + 结论 + 备选 | 任何改架构/主表/API 错误体/安全护栏前先写 |
| 项目计划 | `docs/PLAN.md`（Phase 0~6 进度） | 里程碑进度与当前阶段 | 每阶段完成时更新 |

## 规则

- **权威唯一**：同一件事只在一个文档定义。代码与文档冲突 → 改文档（走 ADR）再改代码，禁止"先写了再说"
- **架构变更门槛**：动技术栈主框架 / API 错误体 / 数据模型主表 / 安全护栏 / 原则 P1-P9 → **必须先写 ADR**，评审通过再改代码
- **文档随代码走**：新增 API 同步 CLAUDE.md §5 + rules/06；新增表同步方案第 7 章 + rules/01 版本清单
- **环境探测结果驱动**：所有"待环境探测确认"项必须由 `docs/环境探测结果.md` 填实，禁凭猜测写死
- 文档语言：中文（本项目约定）；代码注释语言跟随代码语境，保持项目一致
- Markdown 规范：标题层级不超过 4 级；表格用于结构化信息；Mermaid 用于架构/时序/ER 图
- 禁在文档写入密码/token/连接串明文（一律 `<环境变量>` 占位）

## 目录约定

- `docs/` 下按需建子目录（`docs/ADR/` 等），禁随意新增顶层目录（见 02）
- 页面级说明性文档原则上不建（README 已覆盖）；确需才创建，避免文档膨胀
